Why My First Layouts Kept Breaking on Mobile

When I started this module, every page I built looked fine on my laptop and fell apart the moment I resized the browser. Text overflowed its box, my navigation wrapped onto three lines, and images stretched past their containers. It took a while to realise this wasn't bad luck - it was a missing mental model.

The fix wasn't more CSS, it was different CSS

My first instinct was to patch each broken layout with a fixed pixel width. That just moved the problem to the next screen size. Switching to relative units - percentages, rem, and CSS Grid's fr unit - meant the layout could flex instead of snap.

Media queries as a last step, not a first one

The biggest shift for me was designing mobile-first: build the single-column version first, then use a min-width media query to add structure - like the multi-column skills grid - as the viewport grows.

"Make it work, then make it work everywhere." - the rule I now keep coming back to.

What I'd tell myself on day one

Resize the browser constantly while you build, not after. Every layout bug is easier to catch at the moment you introduce it than three sections later when you can't remember which rule caused it.
