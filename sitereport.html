Starting Out

Week one was mostly confusion. I understood what a tag was, but not why the browser rendered a <div> full-width by default, or why a CSS selector wasn't matching the element I wanted. My first version of the home page was a plain block of unstyled text - getting from that to something with real structure took longer than I expected, mostly because I kept nudging things with margin instead of learning the box model properly.

Design Decisions

I went with a dark theme - a near-black background (#0f1115) with a mint accent (#5fd3bc) for headings, links, and buttons, and amber (#f2c14e) as a secondary highlight for things like code snippets and hover states. It reads well for long stretches of text like this report, and it feels closer to a developer's own tool than a plain white page.

Layout-wise I kept things simple and consistent: a centred header, a sticky nav bar, and a single-column main area built from repeated .content-section cards. The skills page breaks that pattern slightly with its card grid, and the projects page uses its own grid again - different content, different shape, same underlying system.

Ups and Downs

The contact form gave me the most trouble. My first attempt used action="mailto:..." without enctype="text/plain", and the fields came through as one unreadable line in the email body. Adding the correct enctype fixed it, but it took a fair bit of searching to understand why. I also caught a typo in my own email address on the contact page while proofreading - a good reminder to actually test the form myself rather than assume it works.

The win was getting the project card grid to reflow properly on mobile using grid-template-columns: repeat(auto-fit, minmax(...)) instead of a fixed column count - one line of CSS replaced three separate media query overrides I'd written before that.
